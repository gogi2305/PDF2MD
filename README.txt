PDF2MD — конвертер и поиск по документам
=========================================
English version: README.md

Закидывайте документы пачкой: целые папки, архивы ZIP / RAR / 7z (в том числе
вложенные друг в друга), PDF, многостраничные TIFF-сканы, фото, Word/Excel —
вперемешку и сколько угодно источников за раз. Программа распознает всё и
покажет в отчёте, где текст мог потеряться: пропавшие и пустые страницы,
мусор вместо текста, расхождения двух OCR-движков.


ЧТО ИЗМЕНИЛОСЬ В ВЕРСИИ 1.3
---------------------------
+ Архивы RAR и 7z — как и ZIP: целиком, со вложенными архивами любого из
  трёх типов. Многотомный RAR (дело.part1.rar, part2.rar, ...) распаковывается
  с первого тома. Распаковка — через 7-Zip (https://www.7-zip.org); без него
  RAR частично откроет встроенный tar Windows 10+, но 7-Zip надёжнее.
  Битый или запароленный архив не останавливает пачку — ошибка будет в логе.
+ TIFF-сканы, в том числе многостраничные (стандарт сканеров и электронных
  архивов): конвертируются в PDF и идут через OCR со сверкой страниц.
  Раньше TIFF молча пропускались.
+ Символические ссылки внутри папок и архивов пропускаются — архив не может
  подсунуть в OCR чужой файл с диска.
+ Тесты: 58.


ЧТО ИЗМЕНИЛОСЬ В ВЕРСИИ 1.2
---------------------------
Главное: результат больше не может «выглядеть готовым», если часть текста
потерялась или устарела.

+ Сверка числа страниц PDF (новый раздел в report.md)
  Каждая страница в .md начинается со скрытой метки <!-- page N -->
  (в просмотрщиках Markdown не видна, в поиск не попадает). Отчёт сравнивает
  число страниц исходника с результатом и показывает пропавшие и пустые
  страницы — например, вклеенный скан в цифровом PDF или страницу, которую
  OCR не распознал. Такой документ сразу помечается «сомнительно».
  Надёжно для текстового слоя и Mistral; для Gemini — по инструкции модели;
  LlamaParse и GLM-OCR пока «не проверено».

+ Gemini: оборванный ответ больше не принимается за результат
  Если ответ упёрся в лимит токенов (MAX_TOKENS), кусок PDF делится пополам
  и распознаётся заново. Если обрывается даже одна страница или картинка —
  файл попадает в ошибки, а не в результат с потерянным концом.

+ Изменённые документы обновляются
  - Конвертация: output/_manifest.json хранит хеш исходника для каждого .md.
    Изменили исходник — при следующем запуске он конвертируется заново.
  - Индекс: при переиндексации старые чанки обновлённого документа удаляются,
    в поиске не остаётся старой и новой версии одновременно.

+ Файлы с одинаковыми именами больше не теряются
  x.pdf из a.zip и из b.zip, источники docs/ и docs.zip, два архива с одним
  именем — всё обрабатывается, совпадения переименовываются (x_2.pdf) с
  пометкой в логе. Один источник, добавленный дважды, обрабатывается один раз.

+ Большие PDF в Gemini не задваиваются
  Слишком большой кусок дорезается сам, а не весь файл заново.

+ Поиск: модель эмбеддингов gemini-embedding-001
  Прежняя text-embedding-004 отключена Google. Старый индекс пересоздаётся
  автоматически при нажатии «Индексировать»; поиск по нему не запускается.

+ Чанки укладываются в лимит
  Длинные абзацы делятся по предложениям (сверхдлинное предложение — по словам),
  большие таблицы — по строкам с повтором шапки. Раньше абзац мог уйти одним
  куском на 15 000 символов вместо 1 200.

+ Язык
  - Логи, статусы и ошибки — на языке интерфейса (RU/EN).
  - Ответы на вопросы — на языке вопроса.
  - Новая настройка «Язык документов» (для LlamaParse; остальные сервисы
    определяют язык сами). Не зависит от языка интерфейса.

+ Надёжность и безопасность
  - API-ключ Google передаётся в заголовке, а не в URL — не попадает в лог.
  - Mistral удаляет загруженные PDF из своего хранилища после распознавания.
  - Нельзя случайно запустить две задачи сразу (конвертация, индексация,
    поиск) — сообщения в окне больше не смешиваются.
  - Лаунчеры проверяют, что зависимости реально установлены, а не наличие
    файла-маркера: скопированная папка на чистом ПК поставит их сама.

+ Тесты: 51 вместо 12 (см. ниже).

Обновление с прошлой версии
  - Индекс нужно один раз пересобрать кнопкой «Индексировать»
    (тратит запросы к эмбеддингам на все чанки).
  - Готовые .md прошлой версии не переделываются: при первом запуске их хеши
    просто записываются в манифест, дальше изменения отслеживаются.
  - Файлы из ZIP внутри папки теперь лежат с именем архива в пути
    (markdown/a/x.md вместо markdown/x.md) — такие файлы сконвертируются
    заново (OCR-кэш сбережёт квоту). Старые .md по прежним путям можно удалить.
  - .md прошлой версии и результаты из OCR-кэша не содержат меток страниц —
    в отчёте они будут «не проверено».


=== ГОТОВАЯ ПРОГРАММА ДЛЯ WINDOWS (без установки Python) ===
Скачайте PDF2MD.exe со страницы релизов:
  https://github.com/gogi2305/PDF2MD/releases/latest
и запустите. Результаты сохраняются в папку output рядом с .exe
(или в Документы\PDF2MD, если туда нельзя писать). Для архивов RAR/7z
дополнительно установите 7-Zip: https://www.7-zip.org
Первый запуск занимает несколько секунд: программа распаковывает себя
во временную папку. Файл не подписан цифровой подписью, поэтому Windows
может показать «Система Windows защитила ваш компьютер» — нажмите
«Подробнее» → «Выполнить в любом случае».


=== ЗАПУСК ИЗ ИСХОДНИКОВ ===
Windows: двойной клик по PDF2MD.bat
Linux:   bash PDF2MD.sh   (или chmod +x PDF2MD.sh && ./PDF2MD.sh)
macOS:   chmod +x PDF2MD.command, затем двойной клик.
         Первый раз macOS может блокировать: правый клик по файлу -> Открыть,
         либо в терминале: xattr -d com.apple.quarantine PDF2MD.command
Если GUI не стартует (нет tkinter):
   Linux: sudo apt install python3-tk python3-venv   |  macOS: brew install python-tk
Диагностика окружения: DIAGNOSE.bat (Windows) / bash DIAGNOSE.sh (Mac/Linux)


ЧТО ДЕЛАЕТ:
  1. Конвертирует в Markdown — пачкой, из папок и архивов ZIP/RAR/7z:
     - сканы PDF, TIFF и фото (JPG/PNG/WEBP) — через LlamaParse/Gemini/Mistral/GLM-OCR (OCR)
     - цифровые PDF — напрямую из текстового слоя (без OCR)
     - Word/Excel/PPTX/HTML/CSV/JSON/EPUB и т.п. — через MarkItDown (без OCR)
  2. Проверяет результат: отчёт о сомнительных документах и сверка страниц
  3. Индексирует Markdown-чанки в локальный векторный индекс
  4. Отвечает на вопросы по документам, цитируя источники


КАК ЗАПУСТИТЬ:
  1. Установите Python 3.10+ с https://www.python.org/downloads/
     ВАЖНО: галочка "Add Python to PATH" при установке.
     Для Word/Excel/PPTX нужен Python 3.12 или 3.13 (на 3.14 MarkItDown
     пока не ставится; PDF, сканы и картинки работают на любом).
  2. Двойной клик по PDF2MD.bat
     (если зависимостей нет — лаунчер поставит их сам, 2-3 минуты)
  3. Откроется окно с двумя вкладками. Язык интерфейса — вверху окна.
  Для архивов RAR и 7z установите 7-Zip: https://www.7-zip.org
  (Linux: sudo apt install p7zip-full; macOS: brew install sevenzip). ZIP — без него.


ВКЛАДКА "Конвертация → Markdown":
  - Добавьте папки, архивы (ZIP/RAR/7z) и файлы — сколько угодно и вперемешку.
    Папки обходятся целиком, архивы распаковываются вместе с вложенными,
    мусор (__MACOSX, Thumbs.db, ~$временные) отсеивается, файлы с одинаковыми
    именами из разных мест сохраняются оба.
  - Выберите сервис: LlamaParse / Gemini / Mistral / GLM
  - Вставьте API-ключ один раз (сохранится)
  - Язык документов — для LlamaParse (по умолчанию русский)
  - Цифровые PDF (с текстовым слоем) берутся напрямую — без OCR, без квоты
  - Сканы, TIFF и изображения идут через OCR-сервис (с кэшем); TIFF перед
    этим конвертируется в PDF
  - Фото перед OCR готовятся: авто-поворот, размер, контраст
  - Сверка спорных вторым движком — по желанию (нужен ключ второго сервиса)
  - СТАРТ → Markdown в output/markdown/, чанки в output/chunks/
  - Готовые файлы пропускаются, изменённые исходники — переделываются

  Отчёт output/report.md (на языке интерфейса — русском или английском):
  - «Сомнительно» / «Стоит глянуть» — документы с признаками мусора
    (пусто, [неразборчиво], искажённые слова) или с потерянными страницами
  - «Сверка страниц PDF» — где распознано меньше страниц, чем в исходнике,
    и какие страницы пустые
  - «Сверка двух движков» — где второй OCR прочитал иначе (diff в report_diffs/)
  - report.json — то же для машинной обработки; поле level там всегда
    одно из «надёжно» / «проверить» / «сомнительно», независимо от языка

  ВАЖНО: «надёжно» значит «явного мусора не найдено», а не «точно».
  Гладко прочитанная, но неверная цифра или фамилия эту проверку пройдёт.
  Ключевые реквизиты сверяйте с оригиналом.


ВКЛАДКА "Поиск по документам":
  Шаг 1. Индексация:
    - Папка с чанками = output/chunks
    - Папка индекса = output/index
    - Кнопка "Индексировать" → векторы через Gemini embeddings
      (gemini-embedding-001; нужен Gemini-ключ с вкладки «Конвертация»)
    - Повторный запуск добавляет новые чанки и убирает устаревшие чанки
      обновлённых документов. Документы, удалённые из папки чанков целиком,
      остаются в индексе — чтобы начать с нуля, удалите папку индекса.

  Шаг 2. Вопросы:
    - Gemini (облако) или Ollama (локально)
    - Ответ ТОЛЬКО на основе найденных чанков + ссылки на источники
    - Ответ — на языке вопроса; обрезанный по длине ответ помечается

  Одновременно выполняется одна задача: пока идёт конвертация, индексация
  или поиск, вторую запустить нельзя.


ГДЕ ХРАНИТСЯ:
  - API-ключи и настройки: %APPDATA%\pdf2md\config.json  (Windows) / ~/pdf2md/ (Linux/macOS)
  - Markdown:         output/markdown/   (с метками страниц <!-- page N -->)
  - JSON-чанки:       output/chunks/
  - Векторный индекс: output/index/
  - OCR-кэш:          output/_ocr_cache/  (повтор того же файла не тратит квоту)
  - Манифест:         output/_manifest.json  (хеши исходников: изменённый
                      документ при следующем запуске конвертируется заново)
  - Отчёт:            output/report.md, output/report.json, output/report_diffs/

СТРУКТУРА ПРОЕКТА:
  app.py                  Точка входа (запускается лаунчерами)
  pdf2md/
    constants.py          Пути, расширения, языки документов, имена файлов
    i18n.py               Тексты окна RU/EN (кнопки, подписи), подписи сервисов
    messages.py           Тексты логов и ошибок RU/EN, выбор языка
    compat.py             Опциональные зависимости (requests/numpy)
    config_store.py       config.json (API-ключи, язык, настройки)
    archives.py           Распаковка RAR/7z (7-Zip, bsdtar, py7zr)
    fileutils.py          ZIP/папки/мусор, тип файла, уникальные имена
    ocr_cache.py          Кэш OCR по хешу содержимого
    imaging.py            Подготовка фото перед OCR, TIFF → PDF
    pages.py              Метки страниц и сверка числа страниц
    chunking.py           Разбиение Markdown на чанки (с делением длинных блоков)
    pdf_native.py         Текстовый слой PDF, разбивка PDF, MarkItDown
    ocr_clients.py        LlamaParse / Gemini / Mistral / GLM клиенты
    index.py              Эмбеддинги + векторный индекс (numpy)
    answerers.py          Gemini / Ollama — ответы по чанкам
    quality.py            Оценка достоверности + сверка движков
    workers.py            ConvertWorker / IndexWorker / SearchWorker, манифест, отчёт
    gui.py                Tkinter-интерфейс (вкладки, обработчики)
  tests/                  58 тестов на pytest, без сети и API-ключей:
    test_pdf2md_smoke.py    дымовые тесты всех модулей
    test_fixes.py           ключ в заголовке, эмбеддинги, язык, имена, Mistral
    test_robustness.py      обрыв Gemini, обновление документов, чанки, GUI
    test_pages.py           метки страниц и сверка в отчёте
    test_archives.py        RAR/7z, вложенные архивы, тома, TIFF

  Запуск тестов:  pip install -r requirements-dev.txt && pytest tests/ -v
  Тесты не обращаются к реальным OCR-API — ответы сервисов подменяются.
